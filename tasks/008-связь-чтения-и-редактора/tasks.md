# 008-связь-чтения-и-редактора: одно место в тексте при переходе между Read и Edit

**Контекст:** читая, владелец замечает опечатку или неточность, переходит в Edit и ищет это место в исходнике глазами. Отрисованный текст сейчас никак не связан со строками исходника: `parseMd` выдает HTML без номеров строк, синхронной прокрутки нет, только оглавление в Edit ищет заголовок по тексту.

## Постановка

**Критерии готовности** (фичи целиком, словами владельца):
1. Читаю, выделяю слово, жму Ctrl+E — в редакторе выделено это же слово.
2. Если выделение захватило жирный текст или ссылку и точного совпадения в исходнике нет, курсор стоит в начале нужного абзаца, пункта или строки таблицы, а не в начале файла.
3. Без выделения Ctrl+E ставит курсор в начало блока, который сейчас вверху экрана.
4. Ctrl+E из редактора открывает чтение на том месте, где стоит курсор.
5. (Отложено, T-02) В Edit превью прокручивается вместе с редактором и наоборот, панели не дергают друг друга.

**Обстоятельства:** код живет долго, это основная читалка владельца. Ломать нельзя отрисовку, оглавление, отметки изменений, запоминание места чтения, горячие клавиши. После правок — пересборка `python -m PyInstaller --noconfirm MDLook.spec` и установка в `C:\Program Files\MDLook` (`E:\tmp\mdlook-design\deploy.ps1`; запущенную установленную копию закрывать можно). Внешний вид проверять только в окне WebView2, поведение — Playwright-тестами (см. `CLAUDE.md` проекта).

**Необратимое, решаем до исполнения:** нет — файлы документов не меняются.

**Решено не делать:** WYSIWYG. Правка в отрисованном тексте с обратным переводом HTML→Markdown переписывает файлы под git (маркеры списков, переносы, таблицы, формулы, Mermaid). Режим как в Obsidian на CodeMirror 6 — несколько дней и замена всего редактора; MDLook в основном читалка.

## Подробно

### T-01. Ctrl+E переносит место между чтением и редактором [M] <a id="t-01"></a>

**Цель:** при переходе Read → Edit по Ctrl+E редактор открывается на том же тексте (выделение или курсор), при Edit → Read — чтение на блоке с курсором. Сейчас Ctrl+E переключает режим, но редактор открывается в начале файла (`setMode('edit')` ставит курсор в 0).

**Что сделать:**
1. `parseMd` помечает блоки номером строки исходника: `data-line` на абзаце, заголовке, пункте списка, строке таблицы, блоке кода, цитате, `hr`.
   - Учесть сдвиги строк от препроцессинга: `$$…$$` сворачивается в одну строку-плейсхолдер, блоки кода прячутся в `_cbStore` и возвращаются — номер должен указывать на строку исходного `rawMd`.
   - Цитаты разбираются рекурсивным `parseMd(ql.join('\n'))` — передать смещение, чтобы вложенные блоки получили абсолютные номера.
2. Read → Edit по Ctrl+E:
   - есть выделение в `#readerContent` — взять блок с `data-line`, где начинается выделение; найти выделенный текст в строках исходника этого блока (до начала следующего блока); нашелся — выделить его в `#editor`, нет — курсор в начало строки блока;
   - выделения нет — блок, который вверху видимой области `#reader`, курсор в начало его строки;
   - прокрутить `#editor`, чтобы курсор был виден (сейчас `setMode('edit')` сбрасывает курсор и `scrollTop` в 0 через `setTimeout` — не затереть).
3. Edit → Read по Ctrl+E: номер строки под курсором → ближайший блок с `data-line` не больше него → прокрутить `#reader` так, чтобы блок был вверху; свернутые разделы (`.md-section.collapsed`) вокруг него раскрыть, как делает клик в оглавлении.
4. Ctrl+1 / Ctrl+2, вкладки и Ctrl+E из режима Source ведут себя как раньше (без переноса места) — меняется только Ctrl+E между Read и Edit. Решал сам; захочется того же на вкладках — расширить потом.

**Критерий готовности:**
1. Тест: блоки абзаца, заголовка, пункта списка, строки таблицы, блока кода, текста после `$$`-формулы и внутри цитаты получают `data-line`, равный номеру их строки в исходнике.
2. Тест: выделение слова в абзаце + Ctrl+E → `editor.selectionStart/End` охватывают это слово в `rawMd`; повторяющееся в файле слово выбирается в своем блоке, а не первое по файлу.
3. Тест: выделение через границу `**жирного**` → курсор в начале строки блока.
4. Тест: без выделения, прокрутка к середине документа → курсор на строке блока вверху экрана.
5. Тест: курсор в редакторе на строке раздела в середине файла + Ctrl+E → этот блок у верхнего края `#reader`.
6. Все прежние тесты зеленые; проверка в окне WebView2 и в собранном exe настоящими клавишами; установка в Program Files, время `MDLook.exe` совпадает со сборкой.

**Риски:** `data-line` должен попадать в хеши отметок изменений (`mdBlockText`) — не должен: хеш считается по тексту, атрибуты не влияют; проверить тестом `test_changed_blocks_marked_against_previous_view`.

### T-02. Синхронная прокрутка редактора и превью в Edit [M] <a id="t-02"></a>

**Статус:** отложена — решить после того, как владелец поживет с T-01.

**Цель:** в режиме Edit справа всегда видно то место, которое правится, и наоборот: прокрутка превью двигает редактор.

**Что сделать:**
1. Редактор → превью: верхняя видимая строка `#editor` → блок превью с этим `data-line` (интерполяция между соседними блоками) → `#preview.scrollTop`.
2. Высота перенесенных строк textarea: номер строки не задает высоту на экране, если строка переносится. Мерить скрытой копией текста (mirror-div с теми же шрифтом, шириной, `white-space:pre-wrap`), пересчитывать при вводе (с задержкой) и смене ширины.
3. Превью → редактор: верхний видимый блок `#preview` → его `data-line` → смещение строки по той же таблице высот → `#editor.scrollTop`.
4. Защита от зацикливания: прокрутка, вызванная синхронизацией, не порождает обратную (флаг-источник или игнор следующего события scroll).

**Критерий готовности:**
1. Тест: прокрутка `#editor` к строке раздела в середине файла → этот раздел вверху `#preview` с допуском в одну строку.
2. Тест: обратная прокрутка `#preview` → верхняя строка редактора — строка верхнего блока.
3. Тест: длинные переносящиеся строки перед разделом не сбивают совпадение.
4. Тест: одна прокрутка дает ровно одно ответное изменение `scrollTop` другой панели, без качания.
5. Проверка в окне WebView2 колесом мыши; установка в Program Files.
