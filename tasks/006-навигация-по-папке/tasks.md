# 006-навигация-по-папке: Левая панель соседних файлов

**Контекст:** при чтении книги, разбитой на отдельные Markdown-файлы по главам, часто нужно перейти к соседнему файлу из той же папки. Сейчас MDLook умеет открыть файл через системный диалог и перейти по ссылке, но не дает быстрый обзор файлов рядом с текущим документом.

**Выбранное решение:** вариант A — левая всплывающая панель. Панель открывается из toolbar, показывает Markdown/TXT-файлы текущей папки, подсвечивает текущий файл, позволяет фильтровать список и открыть выбранный файл в том же окне.

**Почему не постоянный сайдбар:** справа уже есть `Outline`, а постоянная левая колонка съест ширину чтения. Всплывающая панель сохраняет чистый read-mode и при этом дает быстрый переход по главам.

**Технический факт:** HTML рендерится из временного файла, поэтому браузерный JS не может сам перечислить содержимое исходной папки. Список соседних файлов должен отдавать Python API через `window.pywebview.api`, а frontend только отображает список и вызывает открытие выбранного файла.

## UX contract

- В toolbar появляется кнопка `Folder` рядом с открытием/перезагрузкой файла.
- Клик открывает панель слева поверх документа; повторный клик, `Esc` или клик вне панели закрывает ее.
- Панель показывает только файлы `.md`, `.markdown`, `.txt` из папки текущего файла, без рекурсии.
- Текущий файл подсвечен и не перезагружается при клике.
- Вверху панели есть быстрый фильтр по имени.
- Сортировка естественная: `0088...md` перед `0089...md`, `2.md` перед `10.md`.
- При выборе другого файла он открывается в том же окне, а не в новом.
- Если есть несохраненные изменения, перед переходом показывается существующий `appConfirm`.
- Для нового/несохраненного документа без `filePath` панель показывает empty-state без ошибки.

### T-01. Добавить Python API для списка соседних файлов [S] <a id="t-01"></a>

**Проблема.** `MDLook-template-offline.html` знает `filePath`, но WebView не должен напрямую перечислять локальную файловую систему. Нужен явный backend-метод.

**Что сделать:**
1. В `app.py` добавить helper естественной сортировки имени файла, например `_natural_sort_key(name)`.
2. В `Api` добавить метод `list_sibling_files(self)`.
3. Метод берет `self._current_path`, вычисляет папку и возвращает JSON-совместимый dict:
   - `{'ok': False, 'reason': 'no current file'}` если текущего пути нет;
   - `{'ok': False, 'reason': 'folder not found', 'folder': folder}` если папка исчезла;
   - `{'ok': True, 'folder': folder, 'files': [...]}` при успехе.
4. В `files` включать только обычные файлы с расширениями `.md`, `.markdown`, `.txt`.
5. Для каждого файла вернуть `name`, `path`, `is_current`, `size`, `mtime`.
6. Сортировать список естественно и стабильно по имени.

**Критерий готовности:**
1. В папке с `0088_a.md`, `0089_b.md`, `readme.txt`, `image.png`, `subdir/` API возвращает только первые три файла.
2. Текущий файл имеет `is_current: True`.
3. `2.md` идет раньше `10.md`.
4. При отсутствии текущего файла метод не падает и возвращает `ok: False`.

**Файлы:** `app.py`

### T-02. Добавить Python API для открытия файла по пути в текущем окне [S] <a id="t-02"></a>

**Проблема.** `Api.open_file()` открывает native dialog, а `Api.open_url()` для Markdown сейчас открывает новое MDLook-окно. Для навигации по главам нужно заменить содержимое текущего окна.

**Что сделать:**
1. В `Api` добавить метод `open_file_path(self, path)`.
2. Метод должен принимать только существующие `.md`, `.markdown`, `.txt` файлы.
3. При успехе метод читает UTF-8, обновляет `self._current_path`, `self._file_mtime`, title окна и возвращает `{'ok': True, 'content': content, 'name': basename, 'path': path}`.
4. При ошибках возвращать `{'ok': False, 'reason': ...}` без исключений наружу.
5. Не менять поведение `open_url()`: межфайловые ссылки по Markdown остаются отдельным сценарием и могут открываться в новом окне.

**Критерий готовности:**
1. Клик по файлу в будущей панели может переиспользовать тот же update-flow, что `open_file()`.
2. Попытка открыть `image.png` возвращает `ok: False`.
3. Попытка открыть отсутствующий файл возвращает `ok: False`.
4. После открытия нового файла `reload_file()` работает уже с новым путем.

**Файлы:** `app.py`

### T-04. Связать панель с pywebview bridge [M] <a id="t-04"></a>

**Проблема.** UI панели должен работать в desktop-приложении и в Playwright-тесте с fake `window.pywebview.api`.

**Что сделать:**
1. В `BRIDGE_JS` добавить инициализацию folder navigation только внутри `initBridge()`.
2. При открытии панели вызвать `window.pywebview.api.list_sibling_files()`.
3. Кешировать результат до изменения `filePath`; сбрасывать кеш внутри `updateFileChrome(name, path)`.
4. Отрисовывать список файлов как кнопки, не как ссылки, чтобы не смешивать сценарий с Markdown-ссылками.
5. Фильтр должен работать client-side по `name`.
6. При клике по не текущему файлу:
   - если `hasUnsaved`, спросить `appConfirm('Unsaved changes. Open another file?')`;
   - вызвать `window.pywebview.api.open_file_path(path)`;
   - при `ok` обновить `rawMd`, editor, `hasUnsaved`, `fileName`, `filePath`;
   - вызвать `clearAutoSave()`, `_mdlookResetSearch()`, `setMode('read')`;
   - закрыть панель.
7. `Esc` закрывает панель до обработки остальных Escape-сценариев, если панель открыта.

**Критерий готовности:**
1. Панель открывается без перезагрузки документа.
2. Открытие соседнего файла меняет документ в том же окне.
3. Несохраненные изменения не теряются без подтверждения.
4. После перехода обновляется заголовок окна и `#fn`.
5. После перехода список соседних файлов перестраивается уже для новой папки, если путь изменился.

**Файлы:** `app.py`, `MDLook-template-offline.html`
