# 007-облегчение-сборки: Меньше размер и быстрее старт без смены стека

**Контекст:** папка сборки `dist/MDLook/` весит 82 МБ, первый старт идет около 2 секунд. Обсуждали переписывание на Tauri (Rust-обертка вокруг того же WebView2). Сначала нужно понять, из чего складываются 2 секунды: если основную часть съедает запуск WebView2, Tauri ее не уберет. Эта группа задач замеряет старт, снимает лишний вес в текущем стеке и по итоговому замеру отвечает, нужен ли переход.

## Постановка

**Критерии готовности** (фичи целиком, словами владельца):
1. Известно, из чего складываются ~2 с холодного старта, и по замеру видно, решит ли проблему переход на Tauri.
2. Папка сборки заметно меньше нынешних 82 МБ, функции не потеряны: трей, ассоциации, несколько окон, Mermaid и формулы.
3. Повторное открытие документа не перечитывает и не переписывает шаблон на 7,6 МБ.
4. Документ без диаграмм и формул не тратит время на загрузку Mermaid и KaTeX.

**Обстоятельства:** код рабочий, им пользуются каждый день, установленная копия лежит в `C:\Program Files\MDLook\`. Дорого сломать открытие файлов, ассоциации, несколько окон и переходы между документами в одном окне. Внешний вид проверять только в WebView2, не в headless Chromium (см. `CLAUDE.md`). После правок `app.py` или шаблона — пересборка `python -m PyInstaller --noconfirm MDLook.spec`.

**Необратимое, решаем до исполнения:** нет.

### T-01. Замер холодного старта по этапам [S] <a id="t-01"></a>

**Цель:** разложить ~2 с первого старта собранного `dist/MDLook/MDLook.exe` на этапы, чтобы понять, что доминирует.

**Что сделать:**
1. Добавить в `app.py` отметки времени (`time.perf_counter()` от самого начала модуля) с записью в лог-файл в `%TEMP%`, включаемые переменной окружения, например `MDLOOK_TIMING=1`. Этапы:
   - старт процесса → начало `app.py` (распаковка и инициализация Python; брать время создания процесса через `GetProcessTimes`);
   - цикл удаления Zone.Identifier по всем файлам `_internal`;
   - `import webview` (тянет pythonnet и .NET);
   - `_setup_tray()` (pystray + PIL);
   - `webview.start` → окно показано (инициализация WebView2);
   - `build_html` (чтение 7,6 МБ, замены, запись временного файла);
   - `load_url` → событие загрузки страницы в JS (разбор шаблона, Mermaid, KaTeX, Prism, первый рендер). Метку из JS отдать в Python через `pywebview.api`.
2. Прогнать холодный старт 5 раз с документом `example.md` и 5 раз с крупным реальным Markdown-файлом. Между прогонами закрывать свой процесс по PID (`taskkill /F /PID <pid> /T`), не по имени образа.
3. Записать таблицу медиан по этапам в `tasks/007-облегчение-сборки/замер-до.md`.

**Критерий готовности:**
1. Есть таблица медиан по этапам, сумма этапов сходится с полным временем старта в пределах ~10%.
2. Названо, какой этап доминирует и какая доля приходится на то, что Tauri убрал бы (Python, pythonnet), а какая на WebView2 и разбор страницы.
3. Без переменной окружения поведение и скорость приложения не меняются.

**Файлы:** `app.py`, `MDLook-template-offline.html`, `tasks/007-облегчение-сборки/замер-до.md`

### T-02. Исключить numpy и cryptography из сборки [XS] <a id="t-02"></a>

**Проблема.** В `_internal` лежат numpy с numpy.libs (~27 МБ) и cryptography с OpenSSL (~15 МБ). `app.py` их не импортирует, они попали из окружения, потому что `excludes` в `MDLook.spec` пустой.

**Что сделать:**

2. Добавить `numpy`, `cryptography` в `excludes` в `MDLook.spec`. Если `libssl-3.dll`/`libcrypto-3.dll` и `_ssl` нужны только им — проверить, используется ли `ssl` в `app.py` (`urllib.request` для https), и исключать только если нет.
3. Пересобрать, проверить размер папки и что приложение запускается, открывает файл, показывает трей.

**Критерий готовности:**
1. В `dist/MDLook/_internal` нет numpy и cryptography.
2. Приложение запускается, открывает `.md`, трей работает, ошибок импорта нет.

**Файлы:** `MDLook.spec`

### T-03. Урезать PIL до того, что нужно иконке трея [XS] <a id="t-03"></a>

**Проблема.** PIL занимает 11 МБ, из них 7,5 МБ — `_avif`, ещё `_webp` и `_imagingcms`. Нужен он только трею: `Image.open(ICON_PATH)` в `_setup_tray`. Совсем убрать PIL нельзя без замены pystray: его win32-бэкенд принимает `PIL.Image` и сам сохраняет его в .ico.

**Что сделать:**
1. Исключить в `MDLook.spec` неиспользуемые модули PIL: `PIL._avif`, `PIL.AvifImagePlugin`, `PIL._webp`, `PIL.WebPImagePlugin`, `PIL._imagingcms`, `PIL.ImageCms`, `PIL._imagingtk`, `PIL.ImageTk` и прочие плагины, которые не нужны для чтения .ico.
2. Пересобрать, проверить иконку и меню трея.

**Критерий готовности:**
1. PIL в сборке меньше 3 МБ.
2. Иконка трея отображается, все пункты меню работают.

**Файлы:** `MDLook.spec`

**Зависит от:** T-01

**Отклонённые альтернативы:** свой трей через `Shell_NotifyIcon` на ctypes вместо pystray убрал бы PIL целиком, но это ещё ~2,5 МБ выигрыша ценой переписывания меню трея с галочками. Делать, только если T-06 покажет, что PIL заметен в старте.

### T-04. Грузить шаблон один раз, документ передавать через evaluate_js [M] <a id="t-04"></a>

**Проблема.** `build_html` при каждом открытии документа читает шаблон на 7,6 МБ, подставляет содержимое строковой заменой и пишет новый временный HTML, который WebView2 разбирает заново со всеми библиотеками.

**Что сделать:**
1. Найти все места, где вызывается `build_html` и `load_url`: первый старт (`on_loaded`), новое окно (`_create_window`), открытие файла в текущем окне (`open_file`, `open_file_path`, `reload_file`).
2. Записывать шаблон с мостом `BRIDGE_JS` во временный файл один раз за процесс (или отдавать через встроенный http-сервер pywebview) — без содержимого документа.
3. Добавить в шаблоне JS-функцию загрузки документа (имя, папка, текст, режим read/edit), которая делает то же, что сейчас делается при старте страницы из `md-data`/`md-name`/`md-folder`: рендер, заголовок, сброс поиска, оглавления, состояния панели соседних файлов, позиция прокрутки.
4. Открытие документа в существующем окне — вызов этой функции через `evaluate_js` с JSON-аргументом, без перезагрузки страницы. Новое окно грузит общий шаблон, затем вызывает функцию.
5. Сохранить поведение переходов по якорю (`_goto_target_async`) и подтверждения при несохранённых изменениях.
6. Общий временный файл шаблона не удалять при закрытии одного окна (сейчас `temp_html` хранится на окно и чистится в `_make_on_closing`), удалять только при выходе из процесса.

**Критерий готовности:**
1. Открытие второго документа в окне не вызывает чтение шаблона и запись временного HTML.
2. Работают: открытие через ассоциацию и из уже запущенного экземпляра, панель соседних файлов, перезагрузка при изменении файла, переход по ссылке на другой `.md` с якорем, несколько окон, в том числе закрытие одного из двух окон и открытие документа в оставшемся.
3. Содержимое с `</script>` и не-ASCII символами отображается корректно.
4. Существующие тесты в `tests/` проходят.

**Файлы:** `app.py`, `MDLook-template-offline.html`

### T-05. Ленивая загрузка Mermaid и KaTeX, убрать дубль CSS KaTeX [M] <a id="t-05"></a>

**Проблема.** Mermaid и KaTeX вшиты в шаблон и разбираются при каждой загрузке страницы, даже если в документе нет диаграмм и формул. CSS KaTeX со встроенными шрифтами вшит дважды: строки 230 и 3788 шаблона совпадают байт в байт (~370 КБ).

**Что сделать:**
1. Удалить второй блок `embedded-katex-css`.
2. Вынести JS Mermaid и KaTeX из инлайн-`<script>` в отдельные файлы рядом с шаблоном (добавить их в `datas` в `MDLook.spec`) или в `<script type="text/plain">` с выполнением по требованию.
3. Подгружать их при рендере, только если в документе есть блок ` ```mermaid ` или формула. Повторный рендер не грузит библиотеку снова.
4. Проверить офлайн-режим: CDN-фолбэки в конце шаблона не должны срабатывать, когда локальная копия есть.

**Критерий готовности:**
1. В шаблоне один блок CSS KaTeX.
2. Документ без диаграмм и формул не выполняет код Mermaid и KaTeX (проверка через Playwright: глобалы `mermaid`/`katex` не определены).
3. Документ с диаграммой и формулой отображается как раньше — проверено в WebView2, не в headless.
4. Экспорт в HTML документа с диаграммой и формулой открывается в браузере с диаграммой и формулой, как до правки.

**Файлы:** `MDLook-template-offline.html`, `MDLook.spec`
