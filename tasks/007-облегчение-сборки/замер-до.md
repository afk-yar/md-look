# Замер старта до правок

**Что замерено:** старт процесса `dist/MDLook/MDLook.exe`, когда приложение не запущено, но файлы сборки и WebView2 уже в кеше диска Windows (прогоны подряд). Это не холодный старт после перезагрузки: там добавится чтение с диска, его ещё нужно замерить.

**Как:** `MDLOOK_TIMING=1` пишет метки этапов в `%TEMP%\mdlook-timing.log`, время в мс от создания процесса. Скрипт прогонов — `E:\tmp\mdlook-timing\run.py`, 5 стартов на случай, медианы. Дата: 2026-10-15.

## Итог по этапам (медианы, мс)

|---|---|---|---|

| Создание элемента WebView2 и запуск его процессов | 319 | 275 | нет |
| Разбор шаблона 7,6 МБ и выполнение скриптов, рендер документа | 483 | 696 | нет |
| Внедрение моста pywebview и первая отрисовка | 131 | 310 | частично |
| **Всего до отрисовки** | **1666** | **2089** | |

## Выводы

- Обёртка Python + .NET занимает ~730 мс из 1670 (44%). Это доля, которую убрал бы переход на Tauri.
- WebView2 стоит ~320 мс при любой обёртке.
- Страница стоит ~480 мс на маленьком файле и ~700 мс на книге. Её сокращает ленивая загрузка Mermaid и KaTeX (T-05), а не смена обёртки.
- `build_html` сейчас на критическом пути: во всех прогонах создание WebView2 начинается в ту же миллисекунду, когда кончается `build_html`. Строковые замены по 7,6 МБ держат GIL.
- Внутри текущего стека нельзя убрать ~540 мс: интерпретатор и загрузку .NET.
